# Библиотека: адаптивная вёрстка, сборка и публикация

Практическая работа 6. Приложение из практической работы 5 (вход, роли, защита маршрутов) приведено к адаптивному виду, собирается для веба с параметрами и публикуется на GitHub Pages.

## Запуск для разработки

1. Сервер (разрешены страницы с портов 5555 и 8000):

       node tools/mock-server-pr5.js --port 8080 --origin http://localhost:5555,http://localhost:8000

2. Клиент. Адрес сервера в код не вшит, его задают при запуске:

       flutter pub get
       flutter run -d chrome --web-port=5555 --dart-define=API_BASE_URL=http://localhost:8080/api

Все команды есть в задачах VS Code (`Terminal → Run Task`, файл `.vscode/tasks.json`).

Параметры (`--dart-define=ИМЯ=значение`):

| Имя | По умолчанию | Назначение |
|---|---|---|
| `API_BASE_URL` | `/api` на том же сайте | адрес сервера |
| `INACTIVITY_SECONDS` | 180 | через сколько секунд без действий выйти |
| `INACTIVITY_WARNING_SECONDS` | 30 | за сколько секунд до выхода предупредить |
| `SESSION_MAX_MINUTES` | 480 | предельная длительность сессии, минут |

## Адаптивная вёрстка

Границы классов окна лежат в `lib/core/breakpoints.dart`: до 600 — компактный, от 600 до 1200 — средний, от 1200 — широкий. Раскладку выбирает каркас `lib/widgets/library_scaffold.dart`, списки и плитки решают по доступной ширине (`LayoutBuilder`), а не по размеру окна.

| Ширина | Меню | Списки | Плитки (главная, статистика) | Содержимое |
|---|---|---|---|---|
| 360 | нижняя панель из пяти мест, остальное в «Ещё» | карточки | одна колонка | на всю ширину |
| 768 | боковая полоса, подписи под значками | карточки | две колонки | на всю ширину |
| 1280 | раскрытая боковая полоса, подписи рядом | таблица | три колонки | на всю ширину |
| 1920 | то же | таблица | три колонки (главная), четыре (статистика) | не шире 1280, по центру |

Что исправлено по списку обязательных замечаний:

- формы не шире 720 (`ConstrainedBox`), диалоги не шире 440 (`kDialogMaxWidth`);
- фильтры и кнопки в `Wrap`, длинные названия с `TextOverflow.ellipsis`;
- таблица в прокрутке по обеим осям; когда места для неё меньше `kTableMinWidth` (760), вместо неё карточки;
- всем кнопкам-значкам заданы подсказки (`tooltip`), форма входа работает с клавиатуры (Tab, Shift+Tab, Enter).

## Сборка

Один и тот же порядок на компьютере и в GitHub Actions:

    flutter pub get
    dart format --output=none --set-exit-if-changed lib test
    flutter analyze
    flutter test
    flutter build web --release --wasm --base-href /имя_репозитория/ --dart-define=API_BASE_URL=https://адрес/api
    cp build/web/index.html build/web/404.html

| Параметр | Зачем |
|---|---|
| `--release` | сборка без отладки, малый размер |
| `--base-href /имя/` | сайт на Pages живёт в подкаталоге; без параметра файлы ищутся в корне домена и не находятся |
| `--dart-define=API_BASE_URL=…` | адрес сервера, подставляется при сборке |
| `--wasm` | сборка WebAssembly; браузер без её поддержки получает обычный JS |
| `cp index.html 404.html` | Pages на неизвестный адрес отдаёт `404.html`; копия `index.html` заставляет приложение открыть любую глубокую ссылку самостоятельно |

То же для Windows одной командой: `tools\build-web.bat /library/ http://localhost:8080/api` (задача 8). Проверить сборку так, как её раздаёт Pages (префикс, 404.html, gzip): `node tools/serve-build.js build/web --base /library/ --port 8000` (задача 9), страница открывается по адресу `http://localhost:8000/library/`.

Заставка (`web/index.html`) показывается, пока скачивается приложение, и убирается по событию `flutter-first-frame`. Если загрузчик не скачался, заставка сообщает об ошибке.

### Уменьшение размера

Разделы, нужные не всем (рабочее место, мои выдачи, пользователи, статистика, все формы), подключены как `deferred`: Dart выносит их в отдельные части, и они скачиваются при первом открытии раздела (`lib/widgets/deferred_screen.dart`, все `deferred`-импорты собраны в `lib/lazy_screens.dart`). Сравнение «до» (все разделы в основном файле) и «после» — `tools\measure-builds.bat` (задача 10) пишет `build\size-report.md`. Вариант «до» собирается из временной копии проекта, исходный код не меняется.

| Сборка | Загружается при запуске, КБ | gzip, КБ | Отложенные части, КБ (gzip) |
|---|---:|---:|---:|
| Обычная сборка (`--release`) | 3 024 | 885 | — |
| Обычная + отложенные разделы | 2 977 | 876 | 68 (27), 20 шт. |
| `--wasm` | 2 681 | 998 | — |
| `--wasm` + отложенные разделы | 2 681 | 998 | — |

Размеры в таблице: загрузчик Flutter плюс основной файл (`main.dart.js` или `main.dart.wasm` с `main.dart.mjs`). Движок CanvasKit (около 31 МБ в сборке, 11 МБ после gzip) в таблицу не входит: по умолчанию он скачивается с CDN, а не с вашего сайта.

Вывод. Отложенная загрузка уменьшила основной файл обычной сборки на 47 КБ (на 1,5 %), после gzip на 9 КБ (на 1,0 %): разделы, вынесенные в отдельные части, малы по сравнению с самим фреймворком. Сборка `--wasm` для этого приложения вышла меньше в исходном виде (2681 КБ против 3024 КБ), но после gzip больше (998 КБ против 885 КБ), а `dart2wasm` отложенные части не создаёт, поэтому для неё этот приём ничего не даёт. Обычная сборка с отложенными разделами остаётся запасным вариантом для браузеров без WebAssembly GC.

## Публикация на GitHub Pages

Файл `.github/workflows/deploy.yml` при каждом пуше в `main` проверяет форматирование, запускает анализ и тесты, собирает проект и публикует его.

1. В репозитории: Settings → Pages → Source: **GitHub Actions**.
2. Settings → Secrets and variables → Actions → Variables → переменная `API_BASE_URL` с адресом сервера. Пока она не задана, приложение обращается к `/api` на самом сайте.
3. Сервер должен разрешать запросы со страницы (CORS) с адреса `https://<логин>.github.io` и работать по HTTPS: страница на HTTPS не может обращаться к серверу по обычному HTTP, кроме `localhost`.

Адрес сайта: `https://<логин>.github.io/<имя репозитория>/`.

## Восстановление после потери связи

Список, не получивший ответа, показывает сообщение и сам повторяет запрос каждые несколько секунд; когда сервер вернулся, данные появляются без перезагрузки страницы. Кнопка «Повторить» остаётся на случай, если ждать не хочется. Ответ сервера с ошибкой (например, 500) автоповтор не запускает.

## Учётные записи

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin123` | администратор |
| `librarian` | `librarian123` | библиотекарь |
| `reader` | `reader123` | читатель (читательский билет № 1) |

Новая учётная запись из формы регистрации получает роль читателя.

## Что доступно ролям

| Возможность | читатель | библиотекарь | администратор |
|---|---|---|---|
| Каталог, авторы, жанры, издательства (просмотр) | да | да | да |
| Создание, изменение, мягкое удаление | нет | да | да |
| Читатели | нет | да | да |
| Все выдачи, оформление и приём книг | нет | да | да |
| **Мои выдачи** и продление срока | да | нет | нет |
| **Рабочее место** (быстрая выдача и приём) | нет | да | нет |
| Восстановление, удаление навсегда | нет | нет | да |
| **Пользователи и роли** | нет | нет | да |
| **Статистика** | нет | нет | да |

Таблица описана в коде один раз (`lib/auth/permissions.dart`); меню, кнопки и маршруты берут права оттуда. Это только интерфейс: окончательное решение принимает сервер и отвечает 403.

## Как устроена защита

- `lib/router.dart`: функция `guardLocation` вызывается при каждом переходе и при каждой смене состояния входа (`refreshListenable`). Без входа адрес заменяется на `/login?from=…`, после входа пользователь возвращается на запомненный адрес. Если роли адрес недоступен, показывается экран «Доступ запрещён».
- `lib/auth/route_access.dart`: какое право нужно для адреса; проверка адреса возврата (только внутренние адреса, иначе параметр `from` стал бы открытым перенаправлением).
- `lib/core/api_client.dart`: перехватчик добавляет `Authorization: Bearer …` ко всем запросам, кроме `/auth/*`; при 401 токен обновляется один раз, запрос повторяется; параллельные 401 делят одно обновление; неудача обновления даёт чистый выход без повторов.
- Ответ 403 превращается в сообщение «Недостаточно прав для этого действия. …» с названием нужной роли.

## Жизненный цикл токенов

1. Вход: `POST /auth/login` → пара токенов и профиль. В localStorage сохраняются `auth_access_token`, `auth_refresh_token`, `auth_user`, время начала сессии и последнего действия (в браузере ключи имеют префикс `flutter.`).
2. Перезагрузка страницы: сессия восстанавливается из localStorage; если срок бездействия или предел сессии уже вышли, происходит выход.
3. Запрос получил 401: `POST /auth/refresh` с токеном обновления, новая пара токенов сохраняется (роль берётся из ответа сервера), запрос повторяется.
4. Обновление не удалось (токен отклонён): токены стираются, открывается экран входа с пояснением. Если сервер просто недоступен, сессия не сбрасывается.
5. Выход: токены стираются, серверу отправляется `POST /auth/logout`.
6. Бездействие: предупреждение за 30 секунд и выход через 3 минуты; кнопка «Остаться в системе» продлевает сессию. Независимо от активности сессия заканчивается через 8 часов.

## Проверка вручную

- Просроченный токен: сервер с `--ttl 60`, войти, подождать минуту, открыть любой раздел. В сети (DevTools → Network) виден `401`, затем `POST /auth/refresh` и повтор запроса; пользователь ничего не замечает.
- Цикл запросов исключён: запустить сервер с `--ttl 60`, войти, остановить и снова запустить сервер (токены обновления хранятся в его памяти и пропадают), подождать минуту, пока токен доступа истечёт, и открыть любой раздел. В DevTools → Network виден один `401`, один `POST /auth/refresh` с ответом `401`, после чего приложение открывает экран входа и больше ничего не отправляет.
- Предупреждение о бездействии: запуск `--dart-define=INACTIVITY_SECONDS=30 --dart-define=INACTIVITY_WARNING_SECONDS=10` (задача 6).
- Подмена роли (пункт 17): войти как `reader`, в DevTools → Application → Local Storage → `flutter.auth_user` заменить `\"role\":\"reader\"` на `\"role\":\"admin\"` (внутри значения кавычки с обратной косой чертой), перезагрузить страницу. В меню и списках появятся кнопки администратора, но любая операция записи вернёт 403 с сообщением на экране, потому что токен остался читательским.

## Чего нет на лекционном сервере

Для этих возможностей нужен `tools/mock-server-pr5.js`; на лекционном сервере приложение показывает понятное сообщение:

- смена роли пользователя (`PATCH /users/{id}`);
- продление выдачи (`POST /loans/{id}/extend`);
- обязательность токена при чтении, ограничение списка читателей для читателя, проверка спецсимвола в пароле при регистрации.

Статистика собирается на клиенте из обычных списков (параметр `size=1`, нужен только `total`).

Остальные файлы остались от практических работ 4 и 5: права ролей, вход и обновление токена, сессия, формы, репозитории, списки. Состояния «загрузка», «пусто», «ошибка и повтор» проверяет `app_flow_test.dart`, проверку формы — `entity_form_test.dart` и `app_flow_test.dart`, скрытые по роли элементы — `auth_flow_test.dart`.
